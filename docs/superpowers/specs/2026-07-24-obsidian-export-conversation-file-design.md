# Obsidian Export — Conversation File — Design Spec

**Date:** 2026-07-24  
**Status:** Approved  
**Related:** [2026-07-05-obsidian-export-design.md](./2026-07-05-obsidian-export-design.md), [2026-07-06-obsidian-auto-export-design.md](./2026-07-06-obsidian-auto-export-design.md)

## Overview

When exporting a meeting to Obsidian, append one extra markdown file containing the full meeting transcript (with timestamps, matching the Copy Transcript format) and the existing summary markdown. All AI-generated notes remain unchanged; this file is added deterministically by the Rust backend after the LLM export step.

## Requirements

| ID | Requirement |
|----|-------------|
| OBS-CONV-01 | Every successful Obsidian export includes one extra conversation file in the meeting subfolder |
| OBS-CONV-02 | Conversation file contains the full transcript with `[MM:SS]` timestamps (same logic as Copy Transcript) |
| OBS-CONV-03 | Conversation file includes the summary markdown from the database when available |
| OBS-CONV-04 | When no summary exists, the Resumo section shows `Nenhum resumo gerado ainda.` |
| OBS-CONV-05 | AI-generated notes from the LLM export are unchanged |
| OBS-CONV-06 | Conversation file is not generated by the LLM — built deterministically in Rust |
| OBS-CONV-07 | Applies to both manual export and auto-export after summary |
| OBS-CONV-08 | Re-export replaces the entire meeting folder, including an updated conversation file |
| OBS-CONV-09 | `file_count` in the export result includes the conversation file |

## Decisions

| Decision | Choice |
|----------|--------|
| Generation | Rust backend, after LLM parse, before `write_files_to_temp` |
| Filename | `Conversa — {sanitized meeting title}.md` |
| Timestamp format | `[MM:SS]` recording-relative; fallback to wall-clock `timestamp` field for legacy segments |
| Summary source | Raw `markdown` from `summary_processes.result` JSON (same as `load_summary_markdown`) |
| Language | Brazilian Portuguese for static labels and frontmatter |
| User toggle | None — always included |
| Frontend changes | None |

## File Content Template

```markdown
---
title: Conversa — {meeting title}
date: YYYY-MM-DD
type: conversation
meeting_id: {meeting id}
tags:
  - meeting
  - conversa
---

# {meeting title}

**Data:** {DD/MM/YYYY HH:MM} (local formatting via meeting created_at UTC)

## Transcrição

[00:15] Texto do segmento...
[01:42] Próximo segmento...

## Resumo

{summary markdown from database}

```

When summary is missing or empty:

```markdown
## Resumo

Nenhum resumo gerado ainda.
```

## Architecture

```
export_meeting_to_obsidian()
  ├── load meeting, transcripts, summary (existing)
  ├── call LLM → parse files (existing)
  ├── build_conversation_file(meeting, transcripts, summary)  ← NEW
  ├── files.push(conversation_file)                           ← NEW
  ├── write_files_to_temp(files)
  └── move_temp_to_vault(...)
```

### Timestamp formatting

Mirror `useCopyOperations.handleCopyTranscript`:

- If `audio_start_time` is `Some(seconds)`: format as `[MM:SS]` (zero-padded minutes and seconds)
- If `audio_start_time` is `None`: use the segment's `timestamp` string (wall-clock fallback for legacy data)

### Filename sanitization

Reuse `sanitize_filename` from `writer.rs` on the base name `Conversa — {title}`.

## Files

| File | Change |
|------|--------|
| `frontend/src-tauri/src/obsidian_export/conversation.rs` | **New** — `build_conversation_file()` and timestamp helpers |
| `frontend/src-tauri/src/obsidian_export/service.rs` | Append conversation file to `files` vec before write |
| `frontend/src-tauri/src/obsidian_export/mod.rs` | Export `conversation` module |

No frontend, settings, or prompt changes.

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Empty transcript | Export fails before LLM call (unchanged — no export) |
| LLM export fails | No files written; conversation file not created |
| Summary missing | Conversation file still created; Resumo section shows placeholder |
| Filename collision with LLM output | Unlikely (`Conversa —` prefix); if duplicate after sanitize, last write wins in temp (acceptable) |

## Out of Scope

- Toggle to disable the conversation file
- Separate files for transcript-only or summary-only
- Modifying the LLM prompt or AI-generated note structure
- Speaker diarization labels (not in current transcript model)
- Frontend copy-format sharing (Rust mirrors the logic independently)

## Test Plan

1. Export meeting with transcript only (no summary) → folder contains AI notes + `Conversa — {title}.md` with placeholder Resumo
2. Export meeting with transcript + summary → conversation file has full transcript and summary markdown
3. Timestamps show `[MM:SS]` for segments with `audio_start_time`
4. Legacy segments without `audio_start_time` use wall-clock timestamp fallback
5. Re-export same meeting → conversation file updated in replaced folder
6. Auto-export after summary → conversation file present
7. `file_count` returned to frontend includes the conversation file
8. AI-generated notes unchanged compared to export without this feature (except +1 file in folder)
